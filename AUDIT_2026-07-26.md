## Executive assessment

The project is in healthy active-development shape. It parses under Godot 4.7, the
two important unattended act flows completed, the documented F9 comparison system
really does pause a live performance, and the presentation has a coherent theatrical
identity. The key things to resolve before shipping are not core-simulation failures:

1. Release builds can inherit debug experiment choices from the shared settings file,
   contrary to the stated guarantee that they always use shipped defaults.
2. There are known release blockers: non-commercial music assets, no demo export
   preset, and macOS notarization disabled.
3. A few visual/text legibility issues reduce clarity at normal play/capsule size.
4. The one-file architecture is workable today but needs guardrails before another
   large feature pass.

## Follow-up implemented after this audit

On the same date, the requested visual-experiment pass added **Performer wardrobe
(polished)** to the F9 panel. Its first two versions were rejected on sight ("it just
looks awful"): both hung thin decorative strokes over the jacket, including a cream V
that read as a necklace and cuff marks placed body-relative, which floated in mid-air
nowhere near the IK-solved arms. It was rebuilt a third time as filled shapes pinned to
the figure's own landmarks, in the venue's own palette, with the cuff moved inside
`draw_arm` so it rides the solved wrist. That version is **default on**, verified on
screen at the Small Theatre and the World Arena, through a Spin's profile and reverse,
and against the experiment toggled off (the classic figure is byte-identical). It
changes no pose, hand target, prop layering, collision geometry, or simulation value.

Blackout's dark stretch was rebuilt in the same pass: past the cut the object is gone
for everything, a torch keeps its flame alone (sharing `draw_torch_flame` with the lit
draw, which fixed a flame that visibly halved in size at the cut), and every other prop
becomes a smooth radial afterglow rather than a dimmed shape. The Encore rail card also
now sizes itself to its description; at a fixed 66px it clipped any three-line
challenge through its own bottom border.

The release/debug experiment-state issue below was also addressed: experiment choices
now load and save only in debug builds. A release build keeps its in-code defaults even
when it shares a `user://` folder with a prior debug build. The finding is retained as
the rationale and regression case for that safeguard.

## Findings, in priority order

### Resolved P1 — Release presentation could be changed by a debug-session experiment choice

**Why it matters:** The F9 system is intentionally a safe debug-only comparison tool,
but its selected values are saved in the normal global settings file. `load_settings()`
runs *before* the release-build early return, and it loads `experiments` without an
`OS.is_debug_build()` guard ([Game.gd:995](Game.gd#L995),
[Game.gd:1007](Game.gd#L1007), [Game.gd:3893](Game.gd#L3893)). A player/dev machine
that has previously toggled an experiment in a debug build can therefore make a release
build render a non-default variant. This contradicts the claim in
[Game.gd:731](Game.gd#L731) and [CLAUDE.md:117](CLAUDE.md#L117).

**Implemented fix:** Experiment state now loads and saves only when
`OS.is_debug_build()` is true. Keep a debug-then-release regression check which toggles
every F9 option, restarts a release export, and asserts its chosen branches are the
defaults.

### P1 — Music is explicitly non-commercial in the current tree

`CLAUDE.md` states that the included Suno free-tier tracks are non-commercial and must
be replaced before release ([CLAUDE.md:348](CLAUDE.md#L348)). This is a release blocker,
not a polish item. Record the replacement source/licence beside the new audio files and
run one complete audio-state regression afterwards (menu, hub, act, results, looping,
volume sliders).

### P1 — Shipping/export configuration is incomplete

* The scoped free-demo feature has code and a test override but no real export preset;
  this is already documented as open ([CLAUDE.md:447](CLAUDE.md#L447)). All current
  presets have `custom_features=""` ([export_presets.cfg:8](export_presets.cfg#L8),
  [export_presets.cfg:43](export_presets.cfg#L43),
  [export_presets.cfg:80](export_presets.cfg#L80)). Create and export-test a distinct
  demo preset with the `demo` feature.
* The macOS preset has no configured signing identity and notarization is disabled
  ([export_presets.cfg:27](export_presets.cfg#L27),
  [export_presets.cfg:34](export_presets.cfg#L34)). That is fine during development,
  but it is not distribution-ready. Plan signing, notarization, and a clean-machine
  Gatekeeper test before a public macOS build.

### P2 — Small and low-contrast text is doing important work

The windowed captures show a strong overall art direction, but several important labels
fall below comfortable reading contrast/size at 1280×720:

* The controls screen's inactive bindings, `GAMEPAD` block, lower explanatory text,
  and footer are markedly subdued. There is also a large unused vertical middle area,
  while `OTHER KEYS` and the footer compete near the lower frame.
* During a set, the condition explanation (for example `Cold Hands`) and some secondary
  HUD labels are faint. The transient `PERFECT` callout can visually merge into the
  performer/spotlight instead of reading as immediate feedback.
* The capsule composition is elegant and highly legible for the title, but the tagline
  is too small/low-contrast to rely on after the documented 616×353 store resize.

**Safe visual direction:** Do not replace the warm/dark palette. Increase text alpha
and/or size only for task-critical secondary copy; add a dark translucent backing or
outline behind in-stage timing callouts; tighten the controls screen into two clearer
columns or use the vacant centre for a compact controller diagram. For the capsule,
either omit the tagline at small sizes or give it a size/contrast pass after exporting
the exact Steam dimensions. Validate at 1280×720, 1280×800, 1920×1080, and the actual
store raster—not only at the editor viewport.

### P2 — The experiment descriptions have drifted from the implemented UI

The code’s F9 description still says:

* Talent tree = “a node graph along four branches,” although the documented/implemented
  treatment is now four growth columns.
* Settings = “Same eight rows,” although `settings_input()` and the cards renderer use
  nine rows (music, SFX, four toggles, Controls, Records, Back).

See [Game.gd:743](Game.gd#L743), [Game.gd:3730](Game.gd#L3730), and
[Game.gd:9857](Game.gd#L9857). This is a low-risk documentation/UI-copy fix, but it
matters because F9 is meant to make comparisons unambiguous. The text in `CLAUDE.md`
has a few older “off by default” passages too, while the current defaults are on.

### P2 — Automated coverage is promising but insufficiently systematic

The repository has unusually useful dev harnesses (`--booking`, `--daily`,
`--collcheck`, `--latecatch`, screenshot capture), but no committed test script or
coverage matrix. The one collision result above does **not** prove every prop/count/
pattern/trick combination is clear, especially because the design itself records
accepted near-clearance tradeoffs.

**Safe direction:** Add a non-mutating script/CI job that runs parse check; a booked
act; daily act; all documented collision sweeps; save migration fixtures; and one
windowed screenshot smoke test. Make the job fail on `SCRIPT ERROR`, negative
clearance, or “nothing measured.” Preserve human visual review for artistic judgment.

### P3 — One 11,494-line script is now a change-risk multiplier

`Game.gd` contains simulation, persistence, input, audio generation, every screen,
rendering, dev tools, and test harnesses. The region discipline and `CLAUDE.md` are
good mitigations, and there is no need for a disruptive rewrite now. But the file makes
merge conflicts, accidental cross-system coupling, and incomplete UI-variant updates
more likely.

**Incremental direction:** First extract pure, low-risk data/logic (configuration
tables, save schema/migration, and geometry/calibration helpers) into tested scripts.
Keep the current `Main` scene and behavior unchanged. Establish a small contract for
each screen variant: source of truth for rows, input index mapping, and a screenshot
check. Do not split rendering or gameplay merely for style until the seam has tests.

## Positive findings worth preserving

* F9 is the right interaction model for visual experiments: live comparison, persisted
  debug preference, explicitly debug-gated input, and—critically—simulation pause.
  Preserve that invariant when adding variants.
* The F9 overlay’s size is derived from `EXPERIMENT_DEFS.size()`, so adding a fifth
  experiment will not immediately clip the panel.
* The cash-in HUD communicates the amount at risk, rather than the previous misleading
  “every point is yours” framing ([Game.gd:8120](Game.gd#L8120)).
* The stage, spotlight, framed HUD, warm gold/amber palette, and code-rendered performer
  form a cohesive visual language. Improve legibility locally; do not flatten this into
  a bright generic UI.
* The project has explicit evidence of thinking about real-world failure modes:
  focus-loss/pad-disconnect pausing, debug-save separation, daily seeded acts, and a
  collision harness that warns when it measured nothing.
